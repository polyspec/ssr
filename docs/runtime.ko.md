# 런타임

`Pool::new`은 `entry_path`, `entry_bytes`와 정확한 비공개 서버 경로·바이트의 `chunks`를 담은
`ServerBundle`, 0보다 큰 워커 수, 대기열 용량,
0보다 큰 실행 제한 시간을 받는다. 풀은 V8 스냅샷에서 진입점을 모듈로 평가하고, 워커마다
하나의 스레드에서 스냅샷으로 만든 isolate를 소유한다. 진입점은 `render(props, state)`를
export하며 함수는 context 데이터에 보관되고 전역 객체에는 없다. 제공된 모든 서버 파일은 풀 생성 시
컴파일하고 정적 import를 해석하며, 동적 청크는 import할 때 평가한다. 정적·동적 상대 import는 제공된
서버 파일만 대상으로 해석한다. 누락·중복 파일, 잘못된 경로, import 속성, 평가 실패와 끝나지 않은
최상위 await는 오류다. JavaScript 구문 오류는 V8 `SyntaxError` 진단을 JavaScript 오류로 반환한다.
서버 파일 경로는 `server/`로 시작하고 `.js`로 끝나며 빈 요소, 점 요소,
역슬래시, 콜론, 제어 문자가 없어야 한다. import 지정자는 query와 fragment가 없는 상대 경로다.
유효한 정적 import 순환은 V8 모듈 평가를 따른다. 각 파일은 매니페스트
경로를 JavaScript 소스 이름으로 사용하므로 해당 소스맵이 스택 위치를 해석한다. 렌더 함수는 필수 문자열
`html`, `head`와 JSON `state` 값이 있는 객체를 직접 또는 Promise로 반환한다. head 누락이나
잘못된 값은 오류이며 UTF-8 바이트가 `RenderResult`에 남는다. 런타임은
Promise의 결과를 읽기 전에 대기 중인 V8 microtask를 완료한다. Promise가 거부되면
메시지와 stack을 가진 JavaScript 오류를 반환한다. microtask 완료 후에도 대기하는
Promise는 이를 완료할 외부 이벤트 원천이 없으므로 오류다. 함수 부재, 잘못된 결과,
JavaScript 예외도 오류다. 호출자는 SSR `Page`를 전달하고 `RenderResult`를 받는다.
라이브러리 워크스페이스는 S-4-2에서 검증한 같은 V8 150.4.0 소스 체크아웃을 선택하고,
관리 중인 식별자 매크로 의존성을 `Cargo.lock`에 고정한다.

스냅샷 캐시 키에는 정렬된 서버 파일 경로와 바이트의 SHA-256, 워크스페이스 명세에 고정된 deno_core 버전,
라이브러리 패키지 버전이 들어간다. 풀이 스냅샷을 보유하는 동안 같은 키는 이를 재사용하고,
키가 달라지면 새 스냅샷을 만든다. 캐시는 약한 참조를 보유하므로 사용하지 않는 스냅샷
바이트는 해제된다. 번들 초기화 또는 스냅샷 생성에 실패하면 오류를 반환하고, 초기화에도 설정한
제한 시간을 적용한다. 호출마다
워커 isolate 안에 스냅샷에서 별도 V8 context를 복원하며 번들을 다시 실행하지 않는다.
초기화한 서버 전역과 Web API는 각 context에 제공되고, 한 요청에서 바꾼 값은 다른 요청에
영향을 주지 않는다. Props와 입력 상태는 V8 값으로
전달한다. HTML, head, 출력 상태는 바이트로 가져오고, 출력 상태는 ordered-json으로 파싱한다.
각 스냅샷은 독립적인 V8 isolate group을 소유한다. 생성자와 모든 워커 isolate가 같은 group을
사용하므로 서로 다른 애플리케이션 스냅샷을 워커가 동시에 복원할 수 있다. release 소스 빌드는 포인터 압축,
별도 포인터 cage 및 외부 코드 공간을 활성화하며, group을 사용할 수 없으면 오류를 반환한다.
스냅샷과 워커 isolate가 해제될 때까지 group을 유지한다. group 사이의 워커 isolate 복원은 직렬화하지 않는다.
출력 상태에 undefined, 함수, symbol, bigint 또는 유한하지 않은 숫자가 있으면
조용히 제외하거나 null로 바꾸지 않고 실패한다. 잘못된 입출력은 기본값으로 바꾸지 않고
오류를 반환한다.

`render_with_metrics`는 워커를 얻기 전 측정한 대기 시간과 성공한 렌더 직후 해당 워커에서
측정한 V8 사용 힙 바이트를 반환한다. 일반 `render` 호출은 메트릭 없이 같은 렌더 결과를 반환한다.

모든 워커가 실행 중일 때 설정한 수만큼의 호출만 대기할 수 있다. 추가 호출은
`QueueFull`을 반환한다. 하나의 기한이 대기와 스크립트 실행에 적용된다. 기한에
도달하면 V8 실행 종료를 요청하고 최대 1초 동안 워커의 종료와 종료 상태 정리를
기다린다. 워커가 종료되면 `Timeout`을 반환하고 다시 사용할 수 있다. 응답이 없으면
`WorkerUnresponsive`를 반환하고 풀 용량에서 해당 워커를 제외하며, 풀을 제거할 때
그 스레드를 무한정 기다리지 않는다. V8은 멈춘 네이티브 콜백을 중단할 수 없으므로
해당 스레드는 프로세스 종료까지 남을 수 있다. 마지막 워커를 잃으면 대기 호출을
깨우고 워커 오류를 반환한다. 워커 초기화와 실패는 오류다.

복원한 context는 진단을 표준 오류에 기록하는 `console` 메서드와 운영체제 난수를 사용하는
`crypto.getRandomValues`를 제공한다. 난수 메서드는 최대 65,536바이트의 정수
typed-array view를 받고 해당 view만 변경한다. 잘못된 인자, 정수가 아닌 view 및
초과 길이는 오류를 던진다. 두 Web Crypto 오류에 필요한 DOMException 이름과 코드를
제공하며, 관련 없는 DOM API는 없다. 운영체제 오류가 나면 view를 변경하지 않는다.
`fetch`, 파일·네트워크 접근 및 I/O 타이머는 없다. 서버 번들은 신뢰하는 애플리케이션 코드이며
프로세스 격리를 얻지는 않는다.

모든 렌더 context는 UTF-8 `encoding`, `encode`, `encodeInto`를 가진 `TextEncoder`도 제공한다.
인코딩은 단독 서로게이트를 U+FFFD로 바꾼다. `encodeInto`는 UTF-8 시퀀스 일부를 쓰지
않고 읽은 UTF-16 코드 단위와 쓴 바이트의 수를 반환한다. 잘못된 수신자와 대상은
TypeError를 던진다. 이 인터페이스는 React 서버 번들이 필요한 인코딩을 제공하며
파일·네트워크·타이머 연산을 노출하지 않는다.

React 실행 경계에서는 프레임워크와 애플리케이션 번들을 하나의 V8 context에서 실행해
애플리케이션 모듈 초기화가 동일한 React 인스턴스를 사용한다. 프레임워크 번들은 작업 예약
타이머를 어휘 인자로 받는 함수로 실행하고 애플리케이션 번들 실행 전에 전역 타이머를 제거한다.
fixture는 최상위 React 클래스와 context를 `useId`, `useContext`와 함께 렌더하고,
애플리케이션 코드에서 `setTimeout`에 접근할 수 없음을 확인한다.

완료 기준: 추적되는 테스트가 스냅샷 재사용과 키 불일치, 초기화 상태 복원, 초기화 실패와 시간 초과,
요청 격리, 종료되지 않는 스크립트, 대기열 포화,
대기와 실행을 합친 기한, 응답하지 않는 워커의 제외와 대기 호출 통지, 표준 오류에서
확인한 console 출력, 난수와 인자 오류, 금지 API 부재를 검증한다. 각 테스트에는
`make check` 실행 시 제한 시간이 적용되며, 표준 오류 확인 하위 프로세스에도 별도의
제한 시간이 적용된다.
Promise 테스트는 이행, stack을 가진 거부, 완료되지 않은 결과를 확인한다. React 번들
사례는 최상위 React 선언을 가진 애플리케이션 컴포넌트를 실행한다.
