# 렌더 벤치마크

`make bench`는 16개 워커의 스냅샷 런타임에서 고정 SSR 페이지 하나를 렌더한다. 각 호출은 HTML과
상태를 검사한다. 동시 호출 1, 4, 16에서 호출자마다 128번 실행하며 렌더 오류, 표본 누락, 결과 변경
시 실패한다. 성능은 측정하며 실패시키지 않는다. 기록된 한도를 넘은 측정은 `WARNING` 줄을 출력하고,
GitHub Actions에서는 `::warning::` annotation도 출력한다. 빌드는 전체 경과 시간 제한 없이 Cargo 명령과 컴파일러 진행을 기록하며
측정 실행의 제한 시간은 120초다.

벤치마크는 `ssr-runtime`을 `bench` feature로 빌드한다. 이 feature에서 `RenderMetrics::render_cpu`는
렌더 하나에 쓴 워커 thread의 CPU time(`CLOCK_THREAD_CPUTIME_ID`)이며, 컨텍스트 초기화 시작부터
직렬화한 결과까지다. 같은 시간에 실행되는 다른 호출의 CPU time은 포함하지 않는다. 이 feature는
벤치마크 전용이며 공개 API가 아니다.

호출의 wall-clock 시간은 `Pool::render_with_metrics` 직전부터 반환 직후까지다. CPU 처리량은 전체
완료 호출 수를 각 호출의 렌더 CPU time 합으로 나눈 값이고, wall-clock 처리량은 시나리오의 경과
시간으로 나눈 값이다. p50과 p99는 모든 호출의 최근접 순위를 사용한다. 컨텍스트 초기화 시간은 V8
컨텍스트 생성 구간의 wall-clock 시간이다. 메모리는 그 생성 전후의 현재 V8 힙 바이트 변화이며
프로세스 상주 메모리가 아니다. 명령은 관측한 최대 변화를 보고한다.

명령은 CPU 처리량, CPU p99, 최대 힙 변화만 한도와 비교한다. wall-clock 처리량, wall-clock p50과 p99,
컨텍스트 초기화 시간은 보고만 하고 비교하지 않는다. 런타임이 바뀌지 않아도 호스트의 다른 작업이 이
값을 바꾸기 때문이다.

다음 결과는 2026-10-05에 macOS 26.6.2, Apple M3 Pro, 메모리 36 GiB, Rust 1.98.1,
디버그 정보를 비활성화한 Cargo 개발 프로필과 검증한 공식 V8 150.4.0 simdutf release archive에서
호스트 load average가 약 300일 때 측정했다. 호출 지연에는 워커 통신, JSON 해석, 결과 검사가
포함된다. 번들 컴파일과 HTTP 전송은 포함되지 않는다.

유지되는 벤치마크는 시나리오마다 다음 한도를 넘으면 경고한다. 부하가 있는 호스트에서 다섯 번 실행하는 동안
CPU 처리량은 초당 2,108~3,444 렌더였고 CPU p99는 모든 동시 호출에서 1.43 ms 이하였다. 이 한도는 그
변동을 허용하면서도 성능이 크게 저하되면 경고한다.
