# 렌더 벤치마크

`make bench`는 16개 워커의 스냅샷 런타임에서 고정 SSR 페이지 하나를 렌더한다. 각 호출은 HTML과
상태를 검사한다. 동시 호출 1, 4, 16에서 호출자마다 128번 실행하며 렌더 오류, 표본 누락, 결과 변경,
한도 초과 시 실패한다. 빌드는 전체 경과 시간 제한 없이 Cargo 명령과 컴파일러 진행을 기록하며
측정 실행의 제한 시간은 120초다.

각 호출은 `Pool::render_with_metrics` 직전부터 반환 직후까지 두 번 측정한다. 하나는 wall-clock
시간이고 다른 하나는 process CPU time(`CLOCK_PROCESS_CPUTIME_ID`)이다. 렌더는 pool 워커 thread에서
실행되므로 호출 thread의 CPU time만으로는 렌더가 포함되지 않는다. process CPU time에는 호출자, 워커,
V8 thread가 모두 포함된다. 동시 호출 1에서 호출의 process CPU time은 그 호출의 CPU time이다. 동시
호출 4와 16에서는 같은 시간에 실행되는 다른 호출의 CPU time도 포함한다. CPU 처리량은 시나리오의 전체
완료 호출 수를 시나리오의 process CPU time으로 나눈 값이고, wall-clock 처리량은 시나리오의 경과
시간으로 나눈 값이다. p50과 p99는 모든 호출의 최근접 순위를 사용한다. 컨텍스트 초기화 시간은 V8
컨텍스트 생성 구간의 wall-clock 시간이다. 메모리는 그 생성 전후의 현재 V8 힙 바이트 변화이며
프로세스 상주 메모리가 아니다. 명령은 관측한 최대 변화를 보고한다.

명령은 CPU 처리량, CPU p99, 최대 힙 변화만 판정한다. wall-clock 처리량, wall-clock p50과 p99,
컨텍스트 초기화 시간은 보고만 하고 판정하지 않는다. 런타임이 바뀌지 않아도 호스트의 다른 작업이 이
값을 바꾸기 때문이다.

다음 결과는 2026-10-05에 macOS 26.6.2, Apple M3 Pro, 메모리 36 GiB, Rust 1.98.1,
디버그 정보를 비활성화한 Cargo 개발 프로필과 검증한 공식 V8 150.4.0 simdutf release archive에서
호스트 load average가 약 150일 때 측정했다. 호출 지연에는 워커 통신, JSON 해석, 결과 검사가
포함된다. 번들 컴파일과 HTTP 전송은 포함되지 않는다.

유지되는 벤치마크는 시나리오마다 다음 한도를 적용한다. 부하가 있는 호스트에서 측정한 실행들에서
CPU 처리량은 초당 1,961~3,951 렌더였고, CPU p99는 동시 호출 1, 4, 16에서 각각 0.94 ms, 5.75 ms,
76.6 ms 이하였다. 이 한도는 그 변동을 허용하면서도 성능이 크게 저하되면 실패한다.
