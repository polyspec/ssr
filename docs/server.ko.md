# HTTP 서버

`Server::new`는 빌드, 어댑터 선택, 워커 수, 대기열 용량, 렌더 제한 시간을 받는다. 풀을 만들기 전에
공개 파일, 서버 JavaScript 바이트와 SHA-256, 대응하는 비공개 소스맵을 검증한다.
서버 소스맵이 없거나 중복되거나 변경되거나 잘못되면 오류다. 서버는 빌드의 클라이언트와
스타일 URL로 선택한 문서 어댑터를 만든다. `Adapter::React`는 React 어댑터를 선택한다.
서버는 이 선택을 페이지 계약과 분리하여 추가로 지정된 어댑터도 같은 HTTP 경로와 페이지
결과를 사용한다.

`Server::handle`은 바이트 본문을 가진 HTTP 요청을 받는다. `POST /_render`는
`Content-Type: application/json`과 선택적인 `charset=utf-8`, 정확한 페이지 JSON 계약을
요구하며 질의는 오류다. SSR에는 출력
hydration 상태를 포함한 완전한 HTML 문서를, CSR에는 변경하지 않은 입력 상태를 포함한
문서를 반환한다. 잘못된 메서드는 `Allow: POST`와 함께 405이며 HEAD의 본문은 비운다.
잘못된 콘텐츠 타입은 415,
잘못된 페이지는 400을 반환한다. 다른 경로는 기존 공개 파일 제공 함수가 처리한다.
동적 응답에는 `Cache-Control: no-store`와 정확한 바이트 길이를 넣는다.

풀이 가득 차거나 워커를 사용할 수 없으면 503, 렌더 시간이 초과되면 504, 다른 렌더
실패에는 500을 반환한다. JavaScript 오류의 응답과 tracing 이벤트에는 메시지와 소스 위치로
역매핑한 스택을 포함한다. 스택 역매핑이 실패하면 그 원인과 생성된 스택을 보고한다.
소스맵을 해석할 수
없으면 서버 생성이 실패한다. 성공한 SSR 렌더는 렌더 시간, 풀 대기 시간, 현재 V8 힙
바이트를 tracing 이벤트에 기록한다. CSR은 풀 측정값 없이 렌더 시간을 기록한다.

완료 기준: HTTP 테스트가 SSR, CSR, 공개 파일, 잘못된 입력과 메서드 응답을 검사한다.
JavaScript 실패 테스트는 실제 빌드 소스맵과 고정 소스맵의 소스 위치를 검사하고,
메트릭 테스트는 tracing 필드를 검사한다. 빌드 테스트는 비공개 소스맵의 일정한 바이트와
해시를 검증한다.
