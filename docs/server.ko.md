# HTTP 서버

`Server::new`는 빌드, 어댑터 선택과 명시적인 런타임 `PoolOptions`를 받는다. 풀을 만들기 전에
공개 파일, 모든 서버 JavaScript 파일의 바이트와 SHA-256, 각 파일에 대응하는 비공개 소스맵을 검증한다.
서버 소스맵이 없거나 중복되거나 변경되거나 잘못되면 오류다. JavaScript 스택 프레임에는 해당
프레임의 정확한 서버 파일 경로에 대응하는 소스맵을 사용한다. 서버는 빌드의 클라이언트와
스타일 URL로 선택한 문서 어댑터를 만든다. `Adapter::React`는 React 프레임워크와 IIFE
애플리케이션 스트림 경로를 선택한다. 비공개 프레임워크 번들이 필수이고 서버 청크는 거부한다.
`Adapter::Vanilla`는 ECMAScript 모듈 서버 번들을 선택하고 기록된 모든 서버 청크를 평가한다.
`Adapter::Svelte`도 ESM 번들을 사용하고 Svelte head 출력을 문서 head에 넣는다. 두 어댑터는
React 프레임워크 번들을 거부한다. 모든 어댑터는 같은 HTTP 경로와 페이지 결과를 사용한다.
공개 경로는 빌드 매니페스트의 컴포넌트 CSS를 제공한다.

`Server::handle`은 바이트 본문을 가진 HTTP 요청을 받는다. `POST /_render`는
`Content-Type: application/json`과 선택적인 `charset=utf-8`, 정확한 페이지 JSON 계약을
요구하며 질의는 오류다. React SSR은 셸이 준비된 뒤 HTML 스트림을 반환하며 이때 상태와 헤더가
확정된다. CSR은 변경하지 않은 입력 상태를 포함한 완전한 문서를 반환한다. 잘못된 메서드는
`Allow: POST`와 함께 405이며 HEAD의 본문은 비운다. 잘못된 콘텐츠 타입은 415, 잘못된 페이지는
400을 반환한다. 다른 경로는 기존 공개 파일 제공 함수가 처리한다. 동적 응답에는
`Cache-Control: no-store`를 넣는다. 완전한 응답에는 정확한 바이트 길이를 넣지만 스트림 응답에는
본문 길이를 선언하지 않는다.

풀이 가득 차거나 워커를 사용할 수 없으면 503, 렌더 시간이 초과되면 504, React 셸 이전의 렌더·
JavaScript 오류에는 오류 문서와 500을 반환한다. 셸 이후에는 React의 Suspense fallback과
클라이언트 복구 지시를 보낸다. React의 각 `onError` callback은 요청 nonce와 함께 구조화된 tracing
이벤트에 기록하며 React가 제공한 컴포넌트 스택도 보존한다. 이후 전송·렌더 오류가 나면 이미 확정된 응답 상태와
헤더를 유지하고 명시적 스트림 오류로 본문을 끝낸다. 스트림 reader가 청크를 보낸 뒤 거부되면 본문은 그 청크를
먼저 반환하고 JavaScript 거부를 본문 오류로 반환한다. 오류 뒤에 문서 끝 부분을 추가하지 않는다.
각 요청은 운영체제 난수 바이트에서 nonce 하나를 생성해 모든 인라인 script와 style에
적용한다. 난수 실패는 오류다. 셸 이전 JavaScript 오류의 응답과 tracing 이벤트에는 메시지와 소스
위치로 역매핑한 스택을 포함한다. 스택 역매핑이 실패하면 그 원인과 생성된 스택을 보고한다.
소스맵을 해석할 수
없으면 서버 생성이 실패한다. 성공한 SSR 렌더는 렌더 시간, 풀 대기 시간, 현재 V8 힙
바이트를 tracing 이벤트에 기록한다. CSR은 풀 측정값 없이 렌더 시간을 기록한다.

완료 기준: HTTP 테스트가 SSR 셸 시점, 늦은 오류, 청크 경계의 nonce 처리, CSR, 공개 파일,
잘못된 입력과 메서드 응답을 검사한다. 첫 본문 청크 뒤 reader 거부는 초기 상태와 헤더를 유지하고
명시적 본문 오류를 반환한다.
JavaScript 실패 테스트는 실제 빌드 소스맵과 고정 소스맵의 소스 위치를 검사하고,
메트릭 테스트는 tracing 필드를 검사한다. 빌드 테스트는 비공개 소스맵의 일정한 바이트와
해시를 검증한다.

## 개발 모드

`ProcessOptions`는 `ready_timeout`, `drain_timeout`, `restart_limit`, `event_capacity`,
`max_probe_bytes`를 요구한다. 두 시간과 두 용량은 양수이며 값을 암묵적으로 제공하지 않는다.
`ProcessOptions::validate`는 프로세스 시작 전에 이 요구사항을 검사한다.
`event_capacity`는 소스 이벤트와 변경 보고 대기열 각각의 용량이다. 대기열이 가득 차거나 닫히면
거부된 이벤트와 원인을 기록하고 새 요청을 실패시키며 관리를 중지하고 close에서 실패를 보고한다.
소스 경로와 출력 제외를 검사한 뒤 소스 대기열에 이벤트를 추가한다.

`Development::start`는 절대 소스 경로, 명시적 제외 경로, 빌드 `Command`, 완료 빌드 디렉터리와 소유한 소켓 경로로
렌더 `Command`를 만드는 함수, 준비 검증용 SSR `Page`와 명시적 `ProcessOptions`를 받는다. 경로는 심볼릭 링크를 포함하지 않는다. 소스 디렉터리는 재귀적으로 감시한다. 소스 파일은 부모 디렉터리를 비재귀적으로 감시하고
정확한 파일 경로를 대조하여 파일을 교체한 뒤에도 관측을 유지한다. 제외 경로는 소스 경로의 엄격한 하위 경로이며 없는 경로는 기존 상위 경로의 검증을 요구한다.
포함된 입력 경로가 있는 소스 변경만 대기열에 추가하며 경로를 모르는 이벤트도 추가한다.
접근 이벤트는 재빌드하지 않는다. 새 소스 파일도 계속 감시한다. 버려진 파일 이벤트를 알리는 이벤트(`Rescan`)는
모든 경로가 제외 경로가 아니면 재빌드와 경고를 시작한다. 소스 이벤트는 자신과 이미 쌓인 모든 이벤트에 대해 재빌드를 한 번
시작하고, 재빌드가 실행되는 동안 도착한 이벤트는 그 뒤에 정확히 한 번 더 재빌드를 시작한다.

macOS에서 소스 감시는 감시하는 모든 디렉터리와 일반 파일을 `kqueue(2)`에 등록한다. `kqueue(2)`는 등록된 파일의
변경을 daemon을 거치지 않고 kernel에서 알린다. 감시의 walk는 제외 경로를 건너뛴다. 디렉터리가 바뀌면 그 디렉터리를 다시
읽어 새 항목을 생성 알림 전에 등록하고 없어진 항목의 등록을 해제한다. Linux에서 소스 감시는 `inotify(7)`를 쓴다. macOS에서
감시하는 경로마다 file descriptor 하나가 열린다. `Development::start`는 소스 경로를 등록하기 전에 walk의 경로 수를 센다.
이미 열린 descriptor와 함께 soft descriptor limit 안에 들어가지 않으면 soft limit을 그 수만큼 또는 hard limit까지 올리고,
hard limit 안에도 들어가지 않으면 그 수, limit, 가장 큰 디렉터리 다섯 개를 적어 실패한다. 일반 파일도 디렉터리도 아닌 항목은
감시하지 않고 경고로 기록한다.

`Development::start`는 첫 빌드 전에 비공개 디렉터리를 만들고, 소스 경로 다음에 그 디렉터리를 감시하며, 그 안에 sentinel 파일을 쓴다.
첫 빌드는 그 파일의 이벤트가 도착한 뒤에만 시작한다. 이 대기는 시간 제한 없이 기다리며 시작과 끝을 기록한다. 그 전에 도착한
이벤트는 첫 빌드가 읽는 쓰기에 속하므로 재빌드를 시작하지 않고, 그 뒤의 모든 소스 쓰기는 재빌드를 시작하는 이벤트를 만든다.
개발 환경을 닫으면 감시를 멈추고 디렉터리를 제거한다.

두 명령은 Rust 프로그램을 실행한다. 빌드 명령은 `Build::write`가 반환한 불변 디렉터리의 절대
경로와 줄바꿈만 stdout에 기록하고 진단은 stderr에 기록한다. 렌더 명령은 지정된 완료 디렉터리를
전달받은 비공개 Unix 소켓으로 제공하고 수신을 시작한 뒤 그 절대 소켓 경로와 줄바꿈을 stdout에 기록하며 추가 stdout은
금지한다. stdin이 닫히면 새 요청 수락을 중지하고 진행 중인 응답을 완료한다. 관리자는 프로세스
종료 관측과 별도로 자식 stdin을 유지한다. 빌드 출력은 감시 입력 밖 또는 명시적 제외 경로 아래에 둔다.

렌더 프로세스를 게시하기 전에 `Build::read`로 전체 디렉터리를 검증하고 제공된 SSR 페이지를
`/_render`에 요청한다. 준비에는 HTTP 200, HTML 콘텐츠 타입, 비어 있지 않고 `max_probe_bytes` 이내인 완전한 본문이 필요하다. 포트 개방만으로는 충분하지 않다. 준비 제한 시간은 시작과 검증 응답 전체에
적용한다. `Development::from_build`는 이미 완료된 디렉터리와 같은 렌더 명령·페이지·옵션을
받으며 소스 감시나 빌드 명령이 없다.

`Development::handle`은 요청을 비동기로 전달하고 애플리케이션 Host 헤더를 보존하며 Hyper 응답
본문을 반환한다. URI authority는 자식 연결 주소를 선택한다. 해당 본문이
완료되거나 버려질 때까지 프로세스를 유지한다. 교체 후 이전 응답은 완료할 수 있고 새 요청은 준비된
프로세스를 사용한다. 재빌드 또는 감시 실패 시 새 요청은 이후 성공한 재빌드까지 원인과 함께 실패한다.
변경 수신자는 각 결과를 보고한다. 잘못된 초기 빌드는 시작을 실패시킨다. 예상하지 않은 프로세스
종료는 오류 이벤트와 소스 재빌드 없는 동일 검증 빌드의 대체 프로세스 시작을 유발하며
`restart_limit` 이내로 제한한다. 0은 자동 대체를 끈다. 완료 빌드마다 대체 예산 하나를 가지며
성공한 소스 재빌드는 예산을 초기화한다. 대체 준비 실패나 예산 소진 시 요청도 계속 실패한다. HTTP 전송 오류는 하위 원인을 보존한다.

전용 관리 스레드가 Tokio 런타임을 소유한다. `Development::close`는 감시와 실행 중인 빌드를
중지하고 자식 stdin을 닫으며 모든 자식의 종료 상태를 수집한다. 종료 제한 시간을 넘긴 프로세스는
강제 종료하고 종료를 확인하며 종료 함수는 오류를 반환한다. 관리자를 버릴 때도 정리를 기다리고
결과를 기록한다. `close`는 공유 참조를 받으며 동시·반복 호출은 같은 완료 결과를 기다린다.
응답이 끝나지 않아도 교체, 재빌드 실패에 의한 무효화 또는 종료 요청 시 종료 제한 시간을 시작한다.
종료 중 추가 stdout도 오류다. 빌드는 시작·완료·종료 실패·경과 시간과 상속한 stderr를 제공하며 전체 빌드
제한 시간은 없다.

완료 기준: 유지되는 Rust 자식 프로그램은 별도 빌드·렌더 프로세스, 실제 SSR 준비, 명시적 재빌드
실패와 복구, 교체 중 점진적 응답, 완료 빌드의 재시작, 정상 종료, 강제 종료와 관리자 폐기 시
프로세스 정리를 검증한다. 소스 이벤트 테스트는 새 소스 파일을 보존하고 선언된 출력 경로만 제외한다.

`POST /_render`는 JSON 파싱 전에 `max_input_bytes`보다 큰 본문을 HTTP 413으로 거부하며
CSR에도 적용한다. HTTP 전송 계층은 본문을 수신하는 동안에도 같은 한도를 적용해야 한다.

런타임 입력 바이트 한도 초과는 HTTP 413, 대기 수 또는 대기 바이트 한도 초과는 HTTP 503을
반환한다. 정리 실패로 풀을 사용할 수 없으면 헤더 전송 전에 HTTP 503을 반환한다. 출력 한도
초과는 명시적 렌더 또는 응답 본문 오류다.

`Server::health`·`Server::wait`·`Server::close`는 소유한 풀의 가용 상태·종료 이벤트·명시적 종료
결과를 제공한다. 렌더러 프로세스는 종료 이벤트를 사용해 네이티브 작업을 정리하지 못할 때
요청 접수를 중단한다.

감독되는 부모·자식 요청은 비공개 Unix 소켓을 사용한다. 서비스 DNS 이름은 외부 요청 주소로 유지하고 프로세스 준비에서 서비스 주소를 해석하지 않는다. 요청은 전달된 Host 헤더를 유지하며 그 헤더가 없는 요청은 내부 HTTP authority인 `polyspec-ssr-server`를 사용한다.

감독 프로세스는 시작 전에 비공개 소켓 디렉터리를 생성하고 소유하며 렌더 명령 생성 함수에 정확한 소켓 경로를 제공해야 한다. 자식 선언은 그 경로와 같아야 한다. 선언된 경로만으로 삭제를 허용하지 않으며 감독 프로세스는 종료 수집 뒤 자신이 소유한 소켓과 디렉터리만 제거한다. 감독 프로세스는 Unix 소켓 주소보다 긴 소켓 경로를 디렉터리를 만들기 전에 거부한다. 소유한 경로와 다른 선언 경로(네트워크 주소나 상대 경로 포함), 소켓이 아닌 선언 경로, 다른 사용자에게 열린 소켓 디렉터리, 다른 항목이 있는 소켓 디렉터리에 대해 준비는 실패한다. 감독 프로세스는 자신이 만들지 않은 항목을 남기고 디렉터리를 제거하지 못했음을 보고한다.
